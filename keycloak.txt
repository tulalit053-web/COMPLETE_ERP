Istilah Penting dalam Keycloak:
Realm: Ruang kerja atau penyewa (tenant) yang sepenuhnya terisolasi. Sebuah realm mengelola sekumpulan user, credential, role, dan client sendiri tanpa bercampur dengan realm lain. Realm master yang saat ini terbuka di layar Anda adalah bawaan sistem yang fungsinya murni untuk mengelola Keycloak itu sendiri. Data pengguna aplikasi ERP Anda tidak boleh dicampur di sini.   Client: Entitas perangkat lunak yang mendelegasikan proses otentikasinya ke Keycloak. Dalam arsitektur Anda, aplikasi Next.js (frontend) dan Spring Cloud Gateway (backend) bertindak sebagai client.
User: Pengguna akhir atau sistem yang dapat masuk (login) ke dalam aplikasi.Role: Pengelompokan izin atau hak akses (misalnya: admin, keuangan, operasional). Role dilekatkan pada user untuk membatasi apa saja yang bisa mereka akses di dalam aplikasi.Langkah Selanjutnya:Karena Anda saat ini berada di dalam "master realm", Anda perlu membuat realm khusus untuk proyek ini.   

Buat Realm Baru: Di panel kiri atas, klik area dropdown teks "Keycloak" yang berada persis di atas menu "Manage realms". Pilih opsi Create Realm. Beri nama realm tersebut erp-realm, lalu klik Create. Setelah tersimpan, pastikan indikator di kiri atas sudah berubah menjadi erp-realm.   

Buat Client: Di dalam erp-realm, klik menu Clients pada bilah navigasi kiri. Klik tombol Create client. Masukkan erp-client pada kolom Client ID dan klik Next. Pada layar konfigurasi (Capability config), aktifkan opsi Client authentication (ini penting agar Keycloak menghasilkan Client Secret untuk backend Spring Boot Anda), lalu klik Save.   

Buat User Uji Coba: Klik menu Users di bilah navigasi kiri, lalu klik Add user. Isi Username (misalnya test_admin) dan klik Create. Setelah profil pengguna terbuka, masuk ke tab Credentials, klik Set password. Masukkan password yang mudah diingat untuk pengembangan (misalnya 123456), dan matikan toggle Temporary agar Anda tidak diminta mengubah password pada saat percobaan login pertama, lalu simpan.   

Selesaikan ketiga konfigurasi dasar tersebut. Setelah Realm, Client, dan User terbentuk, kita akan mengambil konfigurasi dari Keycloak ini untuk disuntikkan ke dalam application.yml di layanan Spring Cloud Gateway Anda.

Sebagai referensi di masa depan, berikut adalah ringkasan panduan troubleshooting Keycloak saat menghadapi error otentikasi via API (Postman):
Verifikasi Konfigurasi Client: Pastikan Client authentication aktif (untuk menghasilkan Client Secret) dan Direct access grants diaktifkan (wajib agar API bisa menerima otentikasi langsung menggunakan username dan password).Status Password Pengguna: Saat melakukan Set Password untuk user via admin konsol, pastikan toggle Temporary selalu dalam posisi OFF. Jika aktif, API akan diblokir karena sistem menunggu user login via browser untuk mengganti password.Pembersihan Aksi Wajib (Required Actions): Kosongkan semua tag di kolom Required user actions pada profil user agar sistem tidak menahan proses login.Kelengkapan Profil & Verifikasi Email: Keycloak versi terbaru sering menolak login API jika profil dasar kosong. Isi Email, First Name, Last Name, lalu aktifkan toggle Email verified menjadi ON.Pengaturan Login Realm: Di menu Realm settings > Login, pastikan opsi Verify email dalam keadaan OFF agar sistem tidak memaksa alur verifikasi email secara global.Penyesuaian Postman: Pada tab Authorization, ubah Client Authentication menjadi Send client credentials in body (menghindari penolakan header Basic Auth), dan biasakan menekan Clear cookies jika Postman menyimpan cache error sebelumnya.Langkah Selanjutnya:Eksekusi Request: Di Postman, klik tombol Use Token pada pop-up yang sedang terbuka.
